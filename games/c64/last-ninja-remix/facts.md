# Last Ninja Remix — checked facts

- **Boot (live):** first I-TAL disk reaches TSM intro; port 1 fire exits it. Space exits the I+T intro. F7 at the trainer starts the game with unlimited lives and unlimited power both NO. After the Central Park presentation, Space loads the level, and port 2 fire at the credits starts active play. The screenshot is `reference/central-park.png`.
- **Initialized machine (live):** gameplay processor port `$35`, DDR `$2F`; IRQ `$0314=$1E06`, NMI `$0318=$1582`. CIA2 port `$C7` selects VIC bank `$0000`; bitmap mode with `$D018=$19` selects screen `$0400` and bitmap `$2000`.
- **Composition differs (byte comparison):** of 15,889 imported code bytes, 288 differ in the gameplay snapshot: 286 in `$0E00–$0F2B`, one at `$1F5B`, and one at `$8A0F`. Of 45,809 imported data bytes, 4,247 differ. Source bytes therefore come from gameplay, never the composition.
- **Overwritten startup (live trace):** a store checkpoint over `$0E00–$0FFF` fires during movement after four frames, immediately after `$BF02` stores through pointer `$04/$05`. Tracing `$BEC1` reads eight sprite bases from `$169D/$16A5`: `$0C00,$0C40,…,$0DC0`; flag bit 0 adds `$0200`, selecting the other bank. `$BED7/$BEF8` copies decoded sprite masks there. Thus `$0C00–$0FFF` is runtime sprite output in play, including the composition’s former `$0E00` startup code. Stale startup annotations and code typing are removed.

## Verification work

Animation, combat, object records and music remain imported leads. Their previous checks do not verify them here. Later disk loads are out of this declared Central Park scope and remain open under the interim policy in RFC #124.

## Record and decoder checks

- **Main sprite pool (trace and independent decode):** `$CE54-$CF97` holds 162 little-endian biased pointers; adding `$0E54` gives the packed records at `$CF98-$E927`. The decoder at `$BF3F` emits literals, escapes a following literal with `$68`, and emits one to seven zeros for `$69-$6F`. Every record produces exactly 63 bytes and stops at the next pointer boundary. The interactive sprite browser's encoded and decoded arrays match the fresh gameplay capture independently.
- **Auxiliary sprites (trace and independent decode):** each bank at `$E979` and `$F1B2` begins with 40 biased relative words. The compositor computes group base plus word minus `$C000`. All 80 records produce exactly 63 bytes; each stops at the next pointer, and the final records end at `$F1B1` and `$F91F`.
- **Scene records (trace and boundary checks):** 118 words at `$4E27-$4F12` resolve against `$4DE4`, with bit 15 distinguishing leaf records. There are 85 leaves and 33 composites. Each leaf has a size byte followed by ten bytes per cell; every calculated leaf length matches the next record. Composite child commands have three fixed bytes, an optional byte selected by bit 6 of the second byte, and up to three bytes selected by bits 5-6 of the third byte. Each composite ends in `$FF`; all child indices are within the 118-entry table and all boundaries match. Rendering and reflection behaviour still need gameplay checks.
- **Frame descriptors (trace):** 106 absolute pointers at `$C4C2-$C595` select component descriptions. Header bit 7 selects a low-two-bit count plus one; the other path has actor-dependent auxiliary composition. Four-byte components carry sprite selection, X/Y fields and attributes. Some fixed-slot windows extend beyond the next pointer, and trailing bytes in several gaps remain open rather than being silently treated as frame payload.
- **Clipping alias (trace):** `$BDFF` reads `$159D,Y` only with `$F8-$FF`, reaching `$1695-$169C`, the same mask table read directly at `$BDE4`. `$159D` itself lies inside an instruction operand in the text renderer. It is an indexed base alias, not a new routine.
- **UI leaves (trace and boundary checks):** seven consecutive 81-byte images from `$FCC2` through `$FEF8` and the shared image at `$3F40` have size `$42`, four by two cells. The 17-entry directory at `$FCA0` shares these targets. Its last target `$FEF9` has zero dimensions and overlaps the start of collision records; no pixel payload is attributed to that target.

## Live and complete-table checks

- **Decoder execution (live):** ran the original `$BF3F` routine on ten independently decoded records: main indices 0, 1, 100, 159, 160, 161 and both endpoints of both auxiliary banks. The routine returned at the injected caller with X=63, Y equal to the packed length, and all 63 cache bytes matching the independent result. RAM-under-I/O records were tested with the compositor's RAM banking. The saved gameplay state was restored after the tests.
- **Player damage (live and trace):** `$B54A` stores saturated `max(health-damage,0)`. Eight boundary cases include health/damage `(10,3),(10,0),(10,10),(10,11),(0,0),(0,3),(255,254),(255,255)`. Positive remaining health preserves action `$6D` and death latch `$B6`. A zero result sets `$6D=($69>>1)+$24` and `$B6=$FF`. Other combat paths can install hit reactions separately; this describes the damage routine's effect.
- **Projectile collision (live and trace):** `$B767` returns carry clear exactly for horizontal distance below 6 and vertical distance below 8. Ten test pairs cover zero, accepted limits, rejected limits and their negative counterparts. Coordinates were placed away from wraparound; signed world-wrap behaviour is outside these checks.
- **Animation format (trace, independent parse and live step):** the `$C2C4-$C4C1` bank divides into 157 commands across 32 terminated/continued sequences. Every command ends on the next boundary and every frame selector is below 106. Bits 1, 7, 0 and 5 select delay, signed X/Y deltas, event and continuation fields respectively. Executing the first command at `$C2C4` stops before composition at `$A8C3` with control `$1A`, delay/reload 4, frame `$31` and next pointer `$C2C7`, agreeing with the parse. All command/event gameplay outcomes are not covered by this one-step check.
- **Music (live):** after 120 requested frames of normal gameplay, SID voice 1 changes frequency 536 to 1012 and pulse width 2056 to 1028; voice 3 changes frequency 9634 to 7217. This observes the active sequencer while dummy audio keeps the run silent. It does not verify every track command.
- **Mirror lookup tables (complete byte check and trace):** `$1200-$12FF` reverses four two-bit pixel pairs; `$1300-$13FF` reverses eight individual bits. All 256 entries in each table match these formulas. Renderer/blitter consumers index them with the source pixel byte.
- **Text rows and glyphs (complete table check and trace):** 25 words at `$1631` equal `$0400+40*row`; 25 words at `$1663` equal `$2000+320*row`. The inline renderer masks glyph IDs to six bits and copies eight rows from `$1AE8+8*id`. A rendered multicolor atlas establishes space, A-Z and digit ordering; punctuation names remain open. All 23 inline text calls in this occupant still call `$1583` and their four-field headers and zero terminators are checked.
- **Final level hand-over (live):** stopping at loader EOF return `$10F8` captures the complete Central Park replacement before its initializer. `$8A0F` still contains `LDA #$00` there; gameplay contains `RTS`. The complete scene/frame/sprite directories and record pools, font and reversal tables are explicitly retained in the ledger. Additional unchanged loaded ranges reported by `listing.py --entry` remain open.
