# Shinobi analysis log

- The X-Large release's serial transfers took longer than the first screenshot interval. The watch on the buffer store distinguished a live read from a loop waiting indefinitely on the drive.
- The first forced mission captures re-entered the cold-start code and reached screen data where the cold-start code expected setup instructions. The replacement captures enter the resident mission transition at `$B008`. Stopping at its return instruction and entering the player initializer produced playable first-stage snapshots for missions 2–5.
- VICE's native executed-address map gave 1,698 instruction starts during a short Mission 1 sample. The workspace contains the captured map and the separate seed augmented with known engine entry points.
- A store checkpoint at `$4C00` stopped with PC `$1880`, after the cell renderer's store through the second screen pointer at `$187E`. The difference in this range between initial and later mission snapshots is a screen write.
- The scroll dispatch tables identify 16 screen-copy routines at `$2FA7-$3836`. The local annotation pass checked every indexed load and store, both backward branches and the return in each routine. The execution stop and single step for direction 1 are in `work/scroll-dispatch-trace.txt`.
- A load watchpoint at `$CEF8-$CEFF` restricted to `$1E17` confirmed that the alternate scene font extends through its final glyph. The emulator output is in `work/alternate-font-end-trace.txt`.
- The regenerated engine listing reported a short zero-page gap. An execution stop after SETLFS and SETNAM confirmed that `$B9-$BC` hold KERNAL file workspace. The engine ledger excludes those four addresses with the trace evidence.
- The actor updater gets its target from the split pointers at `$9CD3/$9CE2`. Seeding control flow from these addresses exposed routines from `$9DE4` into the `$AD00` page. A controlled type-2 dispatch reached `$A235`. The disassembler initially merged the adjacent setup and update tables into one split table and minted unrelated labels inside code and sprite data. A splitter at `$9CD3` and a restart from the corrected export removed those labels.
- A watchpoint on the final playfield glyph stopped at PC `$1E1E` with the load and store pointers `$D7F8` and `$47F8`. The resident ledger excludes the generated character buffer and the screen work areas while counting the setup code at `$4C00-$4C3D`.
- Controlled probes used the saved gameplay snapshot. The SID store in the effect starter and the panel store from Mission 1 are in `work/sid-effect-trace.txt` and `work/mission1-panel-trace.txt`.
- Typing the dictionary tails caused Regenerator2000 to mint automatic labels again at individual character-pattern pointers. The mission exports clear those labels so each documented dictionary interval owns its slots.

- Controlled CPU stops traced Mission 1's alternate callback, Mission 2's last image row, Mission 3's first moving-block character, and the alternate sprite installs in Missions 4 and 5. The corresponding scripts and logs are in `work/`.
